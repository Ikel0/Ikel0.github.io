MCP : connecter un modèle à un outil ne suffit pas à le rendre utile.

Un protocole peut standardiser une connexion. Il ne décide pas à la place de l’équipe quels outils un assistant doit voir, qui peut les appeler et comment une action doit être vérifiée.

Question de départQuel est le plus petit droit nécessaire pour accomplir une tâche ?

Le branchement technique n’est que le début.

Donner à un modèle l’accès à une recherche, une API ou une base de données peut rendre un assistant réellement utile. Cela ajoute aussi un chemin d’action : une instruction mal comprise, un outil trop large ou un contexte ambigu peuvent produire une requête qui n’aurait jamais dû être exécutée.

Le bon réflexe n’est pas d’interdire les outils. C’est de séparer ce que le modèle propose de ce que le système autorise réellement.

La permission ne doit pas vivre dans le prompt.

Un prompt peut guider un comportement ; il n’est pas une frontière de sécurité. L’autorisation doit être appliquée côté outil ou côté serveur, avec des droits suffisamment précis. Un assistant ne devrait pas lire tous les documents, modifier toutes les lignes ou appeler n’importe quelle opération parce qu’il a reçu un jeton large.

Ce que je retiens pour un premier usage.

  • Commencer par un outil en lecture seule, sur un périmètre réduit.
  • Valider les paramètres avant l’appel, même si le modèle les a proposés.
  • Prévoir une confirmation humaine pour les actions qui modifient une donnée ou déclenchent un effet externe.

Le protocole peut rendre les intégrations plus propres. La confiance vient ensuite du découpage des droits et de la capacité à comprendre ce qui s’est passé.
